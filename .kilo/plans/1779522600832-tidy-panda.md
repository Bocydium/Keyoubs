# UI Modernization Plan

## Issues
1. **Buttons are squished** — fixed sizes and tight padding make UI feel cramped on varying screen sizes.
2. **Wrong Phosphor icon mappings** — semantically incorrect icons on action buttons.
3. **UI looks dated** — hardcoded dimensions, poor sizing policy, no auto-scaling to screen.

## Scope of Changes

### 1. Toolbar (`src/ui/Toolbar.cpp`, `src/ui/Toolbar.hpp`)
- **Remove fixed size constraints**: eliminate `setFixedHeight(42)` and `setMinimumWidth(520)` so the toolbar can auto-size to content and screen.
- **Adjust sizing policy**: set `QSizePolicy::Expanding` horizontally and `Preferred` vertically.
- **Fix icon sematics**:
  - `applyBtn`: change from `Check` (checkmark) → **`FloppyDisk`** (save/apply).
  - `discardBtn`: change from `Trash` (delete) → **`ArrowCounterClockwise`** (revert/undo).
  - `closeBtn`: keep `Cross` (close).
  - `Workspace` tool: change from `SquaresFour` → **`Layout`**.
- **Add padding/spacing**: increase internal padding to prevent squish, ensure adequate spacing between tool buttons and action buttons.
- **Style**: modernize QSS — larger padding, cleaner border radii, slightly increased font sizes.

### 2. PropertyPanel (`src/ui/PropertyPanel.cpp`, `src/ui/PropertyPanel.hpp`)
- **Remove fixed width**: eliminate `setFixedWidth(260)` so the panel flexes with available screen space or at least uses a reasonable `minimumWidth` + `maximumWidth` instead of a hardcoded lock.
- **Better sizing**: use `QSizePolicy` with a reasonable content-based width and respect layout stretches.
- **Spacing & padding**: increase margins and control spacing so it does not look cramped.
- **Style**: modernize QSS — same clean palette and padding, ensure checkboxes and inputs have adequate breathing room.

### 3. OverlayWindow (`src/ui/OverlayWindow.cpp`)
- **Auto-fit geometry**: ensure `updateGeometryForScreens()` correctly repositions and sizes sub-widgets when screen geometry changes.
- **Panel positioning**: when floating/tool positioning is used, compute coordinates using screen-relative proportions rather than absolute pixel assumptions where possible.
- Ensure toolbar and panel do not overlap awkwardly and remain usable across multi-monitor bounds.

### 4. Canvas (`src/ui/Canvas.cpp`)
- Minor cleanup to spacing/margins if any hardcoded coordinates affect perceived density.
- Ensure canvas fills available space with `Expanding` size policy (already set, verify no regressions).

### 5. PhosphorIcons (`src/ui/PhosphorIcons.hpp`)
- Add missing `ColorPicker` and `Measure` constants if they are referenced in `Toolbar.hpp` enum but not defined (currently only Tool enum exists, icons mapped in Toolbar.cpp).
- Verify icon-name strings match available `.svg` resources.

## Testing
- Build and run; verify:
  - Toolbar height is not artificially constrained and buttons have comfortable padding.
  - Property panel width scales with screen and does not truncate content.
  - Each button shows the correct icon.
  - No squishing when window is resized to smaller screens.
